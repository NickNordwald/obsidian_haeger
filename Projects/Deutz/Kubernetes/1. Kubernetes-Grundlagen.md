# Block 1: Kubernetes-Grundlagen

Teil des [[Projects/Deutz/Kubernetes/Kubernetes|Kubernetes-Lernpfads]]. Budget: ~4,5–5 h.

> [!info] So geht's: lesen und nebenher ausführen
> Du folgst der **offiziellen Kubernetes-Doku**. Jede Seite erklärt erst das Konzept und lässt dich dann Schritt für Schritt Befehle ausführen.
>
> 1. **Terminal öffnen:** lokal mit **minikube** (Einrichtung siehe [[Kubernetes Befehlsreferenz#minikube (lokaler Cluster)|Befehlsreferenz]]). Ohne Installation geht es auch im [Kubernetes-Playground auf Killercoda](https://killercoda.com/playgrounds/scenario/kubernetes). Die Doku-Seite und das Terminal nebeneinander öffnen.
> 2. **Lesen und jeden Befehl selbst eintippen**, nicht kopieren. Danach immer kurz `kubectl get …` oder `kubectl describe …` ausführen und schauen, was passiert ist.
> 3. Die Doku geht von minikube aus, die Befehle funktionieren also direkt. Nur im Killercoda-Playground gilt: Abschnitte zum Starten von minikube überspringen, und wo `minikube ip` steht, die `INTERNAL-IP` aus `kubectl get nodes -o wide` nehmen.
> 4. Roh unter **Mitschrift** notieren. Am Ende die **Leitfragen** aus dem Kopf beantworten und „Block 1 reviewen“ sagen.
>
> Am Ende einer Sitzung `minikube stop`, beim nächsten Mal `minikube start`. Der Cluster samt deinen Objekten bleibt erhalten.
>
> **Ab Teil B:** YAML nicht von Hand anfangen, sondern generieren mit `kubectl create … --dry-run=client -o yaml > datei.yaml` und dann anpassen. Felder schlägst du mit `kubectl explain` nach, z. B. `kubectl explain pod.spec.containers.livenessProbe`.

## Teil A: Learn Kubernetes Basics (~1,5 h)

Das offizielle Einsteiger-Tutorial. Eine einzige Beispiel-App wird angelegt, untersucht, erreichbar gemacht, skaliert und aktualisiert. Jedes Modul beginnt mit Erklärtext und Diagrammen, danach folgen die Befehle.

- [x] [Übersicht](https://kubernetes.io/docs/tutorials/kubernetes-basics/), kurz lesen
- [x] [1. Using Minikube to Create a Cluster](https://kubernetes.io/docs/tutorials/kubernetes-basics/create-cluster/cluster-intro/): nur lesen (Cluster, Control Plane, Nodes), minikube nicht installieren
- [ ] [2. Using kubectl to Create a Deployment](https://kubernetes.io/docs/tutorials/kubernetes-basics/deploy-app/deploy-intro/)
- [ ] [3. Viewing Pods and Nodes](https://kubernetes.io/docs/tutorials/kubernetes-basics/explore/explore-intro/): `get`, `describe`, `logs`, `exec`
- [ ] [4. Using a Service to Expose Your App](https://kubernetes.io/docs/tutorials/kubernetes-basics/expose/expose-intro/): Services, Labels
- [ ] [5. Running Multiple Instances of Your App](https://kubernetes.io/docs/tutorials/kubernetes-basics/scale/scale-intro/): skalieren
- [ ] [6. Performing a Rolling Update](https://kubernetes.io/docs/tutorials/kubernetes-basics/update/update-intro/): Update und Rollback

## Teil B: Was die Basics nicht abdecken (~3 h)

Ausgewählte „Tasks“-Seiten der Doku, ebenfalls Erklärung plus Schritte zum Mitmachen. Hier schreibst du die ersten eigenen YAML-Manifeste.

- [ ] **Deklarativ arbeiten:** [Run a Stateless Application Using a Deployment](https://kubernetes.io/docs/tasks/run-application/run-stateless-application-deployment/): dasselbe wie Teil A, aber per YAML und `kubectl apply`
- [ ] **Konfiguration:** [Configure a Pod to Use a ConfigMap](https://kubernetes.io/docs/tasks/configure-pod-container/configure-pod-configmap/). Die Seite ist lang. Mach die Abschnitte zum Anlegen per `--from-literal` und `--from-file`, zur Nutzung als Umgebungsvariablen und zum Einbinden als Volume, der Rest ist Referenz.
- [ ] **Secrets:** [Distribute Credentials Securely Using Secrets](https://kubernetes.io/docs/tasks/inject-data-application/distribute-credentials-secure/)
- [ ] **Probes:** [Configure Liveness, Readiness and Startup Probes](https://kubernetes.io/docs/tasks/configure-pod-container/configure-liveness-readiness-startup-probes/). Exec- und HTTP-Probe mitmachen, dazu Readiness.
- [ ] **Ressourcen:** [Assign Memory Resources to Containers and Pods](https://kubernetes.io/docs/tasks/configure-pod-container/assign-memory-resource/). Hier provozierst du absichtlich ein `OOMKilled`.
- [ ] **CronJobs** ⭐: [Running Automated Tasks with a CronJob](https://kubernetes.io/docs/tasks/job/automated-tasks-with-cron-jobs/), danach das Konzept [CronJob](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/) lesen: Zeitplan, `concurrencyPolicy`, History-Limits. Zusätzlich ausprobieren: `kubectl create job manuell --from=cronjob/hello`.
- [ ] **Debugging:** [Debug Pods](https://kubernetes.io/docs/tasks/debug/debug-application/debug-pods/) und [Debug Services](https://kubernetes.io/docs/tasks/debug/debug-application/debug-service/). Das sind eher Checklisten als Tutorials. Lesen und dabei absichtlich etwas kaputt machen: falscher Image-Tag, falscher Selector.
