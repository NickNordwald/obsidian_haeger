# Block 4: Abschlussübung

Teil des [[Projects/Deutz/Kubernetes/Kubernetes|Kubernetes-Lernpfads]]. Budget: ~1 h. Hier kommt alles aus Block 1–3 zusammen, genau so, wie es im Projekt laufen wird.

> [!info] Arbeitsmodus
> Du schreibst Chart und Manifeste selbst. Claudian reviewt, erklärt und gibt Hinweise, schreibt die Lösung aber nicht vor.
>
> **Umgebung:** im [iximiuz-k3s-Playground](https://labs.iximiuz.com/playgrounds/k3s) oder lokal mit kind. Dazu brauchst du ein **öffentliches Git-Repo**, z. B. auf GitHub, damit Argo CD es lesen kann. Der lokale Code liegt dann unter `~/HaegerConsulting/Projects/Deutz/kubernetes-uebung/`.

## Aufgabe

Ein kleines Helm-Chart `uebung` mit:

- [ ] einem **Deployment**, z. B. `nginx` oder `traefik/whoami`, mit 2 Replikas, Readiness-Probe sowie requests/limits
- [ ] einem **Service** (ClusterIP) davor
- [ ] einer **ConfigMap**, die als Env-Variable eingebunden wird
- [ ] einem **CronJob**, der alle 2 Minuten etwas loggt. Zeitplan und Befehl kommen aus `values.yaml`.

Dann:

- [ ] Chart ins Git-Repo pushen
- [ ] Argo CD im Cluster installieren und eine `Application` anlegen, die auf das Chart zeigt (`syncPolicy.automated`)
- [ ] Im Git `replicaCount` ändern und pushen. Argo CD sollte das ohne `kubectl` ausrollen.
- [ ] Im Cluster per `kubectl scale` „dazwischenfunken“ und beobachten, was Argo CD macht
- [ ] Prüfen, dass der CronJob läuft: Job-Historie und Logs des letzten Laufs
- [ ] Einen Fehler einbauen, z. B. einen falschen Image-Tag, und ihn mit `kubectl` und in der Argo-CD-Oberfläche diagnostizieren
