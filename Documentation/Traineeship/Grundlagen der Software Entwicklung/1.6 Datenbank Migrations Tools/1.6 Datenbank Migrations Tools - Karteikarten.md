## Grundlagen der Datenbank-Migration und Versionierung

Was ist eine Migration?::Eine versionierte, ausführbare Änderung am Schema im Repository, die die DB von einem Zustand in den nächsten überführt. Sie beschreibt einen Weg, keinen Sollzustand.
^q-tvtj

Warum reicht `Base.metadata.create_all()` nicht als Schemaverwaltung?::Es legt nur fehlende Tabellen an und ändert bestehende nie, ohne Fehlermeldung. Es ist deklarativ, eine bestehende DB braucht imperative Übergänge.
^q-i3nt

Was ist Schema-Drift?::Datenbanken, die dasselbe Schema haben sollten, weichen voneinander ab. Migrationswerkzeuge lösen genau das: wissen, welches SQL wo schon lief.
^q-mkv2

Warum editiert man eine ausgelieferte Migration nicht mehr?::Sie läuft auf bereits migrierten DBs nie wieder, es entstünden gleiche Versionen mit verschiedenem Schema. Stattdessen eine neue Migration („roll forward“).
^q-uahj

Was passiert, wenn zwei Branches Migrationen mit demselben Vorgänger anlegen?::Es entstehen zwei Heads, `upgrade head` verweigert den Lauf. Eine Merge-Migration führt sie zusammen, der Konflikt wird sichtbar.
^q-rayf

Warum ist Autogenerate nur ein Entwurf?::Es sieht Zustände, keine Absichten: Eine Umbenennung wird zu Drop und Add mit Datenverlust. Manches erkennt es gar nicht, z. B. `server_default`.
^q-2wfh

Welche drei Bedeutungen hat „Rollback“?::Transaktions-Rollback (DB, verlustfrei), Migrations-Rollback per `downgrade()` (nur Struktur) und Deployment-Rollback (Code springt zurück, Schema nicht).
^q-gfcx

Warum ist `downgrade()` unvollständig, und wofür schreibt man es trotzdem?::Nach `DROP COLUMN` kommt die Spalte leer zurück. In Produktion korrigiert man vorwärts oder nutzt Backups, `downgrade()` dient der lokalen Entwicklung.
^q-z7cp

Warum hinterlässt eine gescheiterte Migration in PostgreSQL keinen Halbzustand, in MySQL schon?::PostgreSQL kann DDL in Transaktionen. MySQL und Oracle committen jede DDL implizit. Regel: eine Migration, eine logische Änderung.
^q-9kci

Was bedeutet N-1-Kompatibilität?::Das neue Schema muss auch mit der vorherigen Codeversion funktionieren, wegen Rolling Deployments und möglicher Code-Rollbacks.
^q-8psn

Welche Schemaänderungen sind zerstörungsfrei, welche zerstörerisch?::Zerstörungsfrei: neue Tabelle, nullable Spalte, Index, Constraint lockern.  
Zerstörerisch: löschen, umbenennen, Typ verengen, Constraint verschärfen.
^q-6nar

Wie funktioniert Expand/Migrate/Contract, z. B. beim Umbenennen einer Spalte?::Expand: neue Spalte anlegen, Code schreibt beide. Migrate: Daten kopieren, Code liest neu.  
Contract: Code nutzt nur neu, dann alte Spalte löschen. Additives vor, Destruktives nach dem Deployment.
^q-jmax

Warum darf eine Migration keine ORM-Modelle importieren?::Die Migration beschreibt das Schema von damals, das Modell das von heute, alte Migrationen brechen dann. Stattdessen rohes SQL per `op.execute()`.
^q-qdd3

Was ist das Lock-Queue-Problem bei Migrationen?::Eine DDL wartet hinter einer langen Query auf ein `ACCESS EXCLUSIVE`-Lock und blockiert alle nachfolgenden Anfragen. Abhilfe: `SET lock_timeout = '3s'`.
^q-dck3

Was ist eine Baseline, und was bedeutet „stempeln“?::Initial-Migration für das bestehende Schema anlegen und bestehende DBs mit ihrer Version markieren, ohne sie auszuführen: Alembic `stamp`, Liquibase `changelog-sync`.
^q-az74

Wie erkennt man, dass ORM-Modelle und Migrationen auseinandergelaufen sind?::Drift-Test in der CI: Schema aus der Kette aufbauen, dann Autogenerate vergleichen. Ein Unterschied macht den Test rot.
^q-u6e8

Wer sollte Migrationen ausführen?::Ein eigener CI/CD-Schritt vor dem Deployment. Beim App-Start migrieren sonst mehrere Instanzen gleichzeitig, und Fehler werden zur Crash-Loop.
^q-axu2

Warum gehören Migrationswerkzeuge zu fast jedem Web-Projekt?::Das Schema ändert sich laufend, es gibt mehrere DBs, Daten lassen sich nicht neu deployen, und Deployments sind automatisiert und nachvollziehbar.
^q-m5si

## Alembic

Warum ist Alembic an SQLAlchemy gebunden?::Autogenerate vergleicht `Base.metadata` mit der per SQLAlchemy-Reflection gelesenen DB, beides derselbe Objekttyp. Ohne SQLAlchemy kein Alembic.
^q-taiv

Welche Dateien legt `alembic init` an?::`alembic.ini` (Konfiguration), `env.py` (Skript, das bei jedem Aufruf die Verbindung aufbaut),  
`script.py.mako` (Vorlage), `versions/` (Migrationen)
^q-4i2z

Was passiert, wenn man `target_metadata` in `env.py` vergisst?::Autogenerate erzeugt leere Migrationen oder will alle Tabellen löschen. Der häufigste Anfängerfehler.
^q-45ap

Warum gehört die DB-URL nach `env.py` statt in `alembic.ini`?::`alembic.ini` ist eingecheckt und Passwörter gehören nicht hinein. `env.py` liest die Konfiguration als Composition Root aus der zentralen Config.
^q-devq

Welche Alembic-Kommandos braucht man am häufigsten?::`revision --autogenerate -m "…"`, `upgrade head`, `downgrade -1`, `current`, `history`, `heads`, `merge`, `stamp`, `check`
^q-wnm5

Wann nutzt man `alembic revision` ohne `--autogenerate`?::Für Umbenennungen, Daten-Migrationen und geänderte CHECK-Ausdrücke, also alles, was ein Diff nicht sehen kann.
^q-pub3

Was erkennt Autogenerate, was nicht?::Erkennt Tabellen, Spalten, Nullbarkeit, Indizes, FKs, benannte Constraints und Typen.  
Nicht: Umbenennungen, anonyme Constraints, CHECK-Ausdrücke und `server_default` (standardmäßig aus).
^q-rnds

Wozu braucht man eine Naming Convention auf dem `MetaData`?::Sonst benennt jede DB Constraints anders, und `op.drop_constraint()` braucht den Namen. Die Convention macht Namen deterministisch.
^q-9kz3

Was prüft `alembic check`, und was nicht?::Ob Autogenerate Unterschiede findet, per Exit-Code für die CI. Es beweist keine Übereinstimmung jenseits dessen, was Autogenerate sieht.
^q-pejv

## Liquibase

Was ist die Kernidee von Liquibase?::Migrationen werden abstrakt beschrieben und in den SQL-Dialekt der Ziel-DB übersetzt. Sprach- und datenbankunabhängig, läuft auf der JVM.
^q-8jfs

Woraus besteht die Identität eines Changesets?::Aus `id`, `author` und `filename`. Umbenennen der Datei macht alle Changesets „neu“, Abhilfe: `logicalFilePath`.
^q-jdgn

Wie bestimmt Liquibase die Reihenfolge?::Über die `<include>`-Reihenfolge im Master-Changelog, ohne Revisionsgraph. Branch-Konflikte werden zu Git-Merge-Konflikten.
^q-u4pz

Was leisten `DATABASECHANGELOG` und `DATABASECHANGELOGLOCK`?::Eine Zeile je Changeset mit Zeitpunkt, `MD5SUM` und Deployment-ID, also ein Audit-Log. Die Lock-Tabelle verhindert parallele Läufe.
^q-jxba

Wozu dient `MD5SUM`?::Liquibase bricht ab, wenn ein ausgeführtes Changeset nachträglich geändert wurde. Unveränderlichkeit wird zur Kontrolle statt zur Disziplin.
^q-tv95

Warum kann Liquibase Rollbacks oft ableiten, Alembic nicht?::Aus einer Beschreibung wie `addColumn` lässt sich `dropColumn` errechnen. Alembics `downgrade()` ist Code und wird immer von Hand geschrieben.
^q-fcgc

Was sind `preConditions`, `contexts` und `labels`?::`preConditions`: Prüfungen vor dem Lauf. `contexts`: wo ein Changeset läuft, z. B. `dev`. `labels`: was es betrifft.
^q-i9zn

Warum vergleicht `liquibase diff` zwei Datenbanken statt Modell und DB?::Liquibase kennt kein ORM-Modell. Wer das Modell als Soll will, ist mit Alembic besser bedient.
^q-ta7h

Wann wählt man Alembic, wann Liquibase?::Alembic: Python-Projekt, in dem SQLAlchemy das Schema besitzt.  
Liquibase: mehrere Sprachen oder DB-Systeme, Audit-Anforderungen oder DBAs ohne Python.
^q-yuak
