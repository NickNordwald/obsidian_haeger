## Block 1: Concurrency vs. Parallelismus und Thread vs. Prozess

Was unterscheidet Concurrency von Parallelismus?::Concurrency: mehrere Aufgaben gleichzeitig in Arbeit, aktiv ist evtl. nur eine. Parallelismus: mehrere laufen im selben Moment auf mehreren Kernen.
^q-iuec

Was meint Rob Pike mit „Concurrency is about structure, parallelism is about execution“?::Concurrency ist die Zerlegung in unabhängige Teile, Parallelismus deren gleichzeitige Ausführung. Dasselbe Programm läuft auf einem oder acht Kernen ohne Codeänderung.
^q-k3j5

Was unterscheidet präemptives von kooperativem Multitasking?::Präemptiv: Das OS unterbricht per Time Slicing jederzeit (Threads, Prozesse). Kooperativ: Die Aufgabe gibt selbst ab, in Python bei `await` (asyncio).
^q-kpzx

Was ist ein Prozess, was ein Thread?::Prozess: laufendes Programm mit eigenem, geschütztem Speicher. Thread: kleinste vom OS verwaltete Einheit, teilt den Speicher seines Prozesses. Jeder Prozess hat einen Main Thread.
^q-f9ca

Was teilen sich die Threads eines Prozesses, und was hat jeder für sich?::Geteilt: Code, Heap mit allen Objekten, offene Dateien. Eigen: Program Counter, Register und Stack mit lokalen Variablen.
^q-9dv7

Woran erkennt man, ob eine Aufgabe I/O-bound oder CPU-bound ist?::Am Engpass: Hilft eine schnellere CPU, ist sie CPU-bound, hilft schnelleres Netz oder Platte, I/O-bound. Das Einlesen und Parsen einer großen CSV ist meist CPU-bound.
^q-49tp

Welche Python-Werkzeuge helfen bei I/O-bound, welche bei CPU-bound Arbeit?::I/O-bound: asyncio und Threads. CPU-bound: Prozesse, im free-threaded Build auch Threads. Bei I/O lässt sich Wartezeit füllen, bei CPU helfen nur mehr Kerne.
^q-sct4

Was unterscheidet Thread und Prozess bei Startkosten, Kommunikation und Absturz?::Start: Thread etwa 100 µs, Prozess etwa 50 ms. Threads teilen Objekte, Prozesse müssen serialisieren.  
Ein Segfault reißt alle Threads mit, Prozesse sind isoliert.
^q-kpqw

Warum ergibt `counter += 1` in zwei Threads nicht zuverlässig das richtige Ergebnis?::Es sind mehrere Schritte: laden, erhöhen, schreiben. Wird dazwischen gewechselt, überschreibt ein Thread das Ergebnis des anderen.
^q-imic

Was sind Race Condition, kritischer Abschnitt und gegenseitiger Ausschluss?::Race Condition: Ergebnis hängt vom Timing ab. Kritischer Abschnitt: Code mit Zugriff auf geteilte Ressourcen.  
Gegenseitiger Ausschluss: höchstens ein Thread darin.
^q-sqjn

Was ist ein Lock, und was kostet es?::Ein Mutex für gegenseitigen Ausschluss, in Python `with lock:`. Kosten: Contention, bei der Threads aufeinander warten, und Deadlocks, vermeidbar durch feste Lock-Reihenfolge.
^q-bxhf

Was unterscheidet Shared Memory von Message Passing?::Shared Memory: gemeinsame Daten, mit Locks geschützt. Message Passing: Austausch nur über Nachrichten (CSP, Go). In Python über eine `Queue`.
^q-ursi

Was sagt Amdahls Gesetz?::Maximaler Speedup $S = 1 / ((1-p) + p/n)$. Bei 90 % parallelisierbar und 4 Kernen etwa 3,1, mit unendlich vielen Kernen höchstens 10.
^q-5kmp

Nach welchem Muster parallelisiert man Datenverarbeitung?::Aufteilen, jeden Teil unabhängig als reine Funktion verarbeiten, Teilergebnisse zusammenführen. Ein passender Aufteilungsschlüssel kann das Zusammenführen ersparen.
^q-sf2k

## Block 2: Warum Python langsam ist und der GIL

Warum ist Python langsam?::Dynamische Typisierung erfordert Typprüfung und Dispatch bei jeder Operation, Bytecode wird interpretiert, und Werte liegen als verstreute Objekte statt dichter Puffer.
^q-vz3y

Warum merken viele Python-Programme nichts von der Langsamkeit?::Sie verbringen die meiste Zeit in C- oder Rust-Bibliotheken, Python ist nur Klebstoff. Langsam wird es, wenn die innere Schleife über die Daten in Python läuft.
^q-8hy7

Wie liegen eine Liste und ein NumPy-Array mit einer Million Ints im Speicher?::Liste: Zeiger auf verstreute `int`-Objekte, etwa 36 MB. NumPy: ein dichter Block roher Werte, etwa 8 MB, cachefreundlich und SIMD-fähig.
^q-juxk

Warum sind pandas, Polars und DuckDB schnell?::Ein Aufruf pro Spalte statt pro Wert, dichter spaltenweiser Speicher, mehrere Kerne ohne GIL und bei Polars und DuckDB ein Query-Optimizer
^q-d78c

Welche Auswege aus der Langsamkeit von reinem Python gibt es?::C- oder Rust-Bibliotheken, PyPy mit JIT, Numba (`@njit`), Cython oder mypyc und eigene Erweiterungen in Rust über PyO3
^q-7bit

Was ist der GIL, und warum gibt es ihn?::Ein Lock pro Interpreter, das nur einen Thread Bytecode ausführen lässt, und schützt so die Interna des Interpreters wie Referenzzähler. Einzelne Operationen wie `list.append()` sind damit sicher, Programmlogik nicht.
^q-4qm5

Warum hielt CPython so lange am GIL fest?::Einfach, schnell bei einem Thread und einfach für C-Erweiterungen, auf denen das Ökosystem aufbaut
^q-7d5z

Wann gibt ein Thread den GIL ab?::Bei blockierendem I/O, in C-Erweiterungen bei reiner Rechenarbeit (z. B. NumPy) und erzwungen nach dem Switch Interval von 5 ms
^q-4229

Wann helfen Threads in CPython mit GIL?::Bei I/O-bound Arbeit und bei Rechenarbeit in C-Bibliotheken, die den GIL freigeben. Nicht bei reinem Python-Rechnen, das wird eher langsamer.
^q-n9gj

Schützt der GIL `counter += 1` vor einer Race Condition?::Nein, er schützt nur einzelne Bytecode-Instruktionen, also die Interna des Interpreters. Für Programmlogik braucht man trotzdem ein Lock.
^q-g4p9

Wie steht es um free-threaded Python?::3.13 experimentell, ab 3.14 offiziell unterstützt, aber optional als eigener Build (`python3.14t`). Der normale Build hat weiterhin einen GIL.
^q-ze62

Welche Falle droht im free-threaded Build bei C-Erweiterungen?::Eine nicht als sicher markierte Erweiterung schaltet beim Import den GIL für den ganzen Prozess wieder ein, nur mit einer Warnung.
^q-mpg3

Was kostet und bringt der free-threaded Build?::Bei einem Thread etwa 5 % bis 10 % langsamer und mehr Speicher. Bei CPU-bound Arbeit auf vier Threads im Test etwa dreimal so schnell.
^q-7zzu

## Block 3: Threads und Prozesse in Python

Wie kommunizieren Prozesse, und was kostet das?::Über Pipes, Sockets oder Memory-mapped Files mit rohen Bytes. Objekte müssen serialisiert werden, das ist teuer, und nicht alles ist serialisierbar.
^q-6mrr

Was ist die große Gefahr von Coroutinen?::Sie geben nur bei `await` ab. Jeder blockierende Code darin blockiert den Event Loop und damit alle anderen Coroutinen.
^q-v9ks

Wie beendet man einen Thread, und warum gibt es keine Kill-API?::Kooperativ über ein `threading.Event` oder eine Poison Pill. Ein von außen abgeschossener Thread könnte Locks halten oder Daten halb verändert hinterlassen.
^q-z8kj

Ein Spinner läuft, während der Main Thread rechnet. Dreht er sich als Thread, Prozess, Coroutine?::Prozess ja, Thread ja (GIL wird alle 5 ms abgegeben), Coroutine nein, weil die Rechnung nie `await` erreicht.
^q-3b52

Was ist die „Thread-Based Nonsolution“ beim Primzahl-Checker?::Mit Threads sieht es parallel aus, ist bei reinem Python-Rechnen wegen des GIL aber nicht schneller. Prozesse skalieren etwa mit der Kernzahl.
^q-rq25

Wie viele Worker nimmt man, und was ist Oversubscription?::CPU-bound: etwa Kernzahl Prozesse. I/O-bound: deutlich mehr Threads. Oversubscription: Prozesse mit intern parallelen Libraries wie Polars erzeugen zu viele Threads.
^q-rsrd

Was bietet `concurrent.futures`?::Executors setzen Concurrency auf bestehenden sequenziellen Code. Der Wechsel zwischen `ThreadPoolExecutor` und `ProcessPoolExecutor` ist eine Zeile.
^q-uz9q

Was ist ein Future?::Ein Platzhalter für ein künftiges Ergebnis, erzeugt von `submit()`. Methoden: `done()`, `result()`, `exception()`, `cancel()`, `add_done_callback()`.
^q-7ist

Was unterscheidet `executor.map()` von `submit()` mit `as_completed()`?::`map` liefert Ergebnisse in Eingabereihenfolge, ein Fehler beendet die Iteration. `as_completed` liefert sie beim Fertigwerden, Fehler pro Future behandelbar.
^q-4ee6

Was passiert mit einer Exception in einem Worker?::Sie wird im Future gespeichert und bei `result()` im Hauptprozess erneut geworfen. Stirbt ein Prozess hart, wird der Pool zu `BrokenProcessPool`.
^q-i5b4

Was unterscheiden `fork`, `spawn` und `forkserver`?::`fork` kopiert den Prozess, schnell, aber mit Threads gefährlich. `spawn` startet frisch (Windows, macOS).  
`forkserver` forkt aus einem sauberen Server, Linux-Standard ab 3.14.
^q-2kz4

Warum braucht ein `multiprocessing`-Skript `if __name__ == "__main__":`?::Bei `spawn` und `forkserver` importiert jedes Kind das Hauptmodul. Ohne Guard startete jedes Kind erneut Prozesse.
^q-x7ys

Was muss über die Prozessgrenze picklebar sein?::Funktionen, Argumente, Rückgaben und Exceptions. Funktionen müssen auf Modulebene stehen, Lambdas, Generatoren, Locks und DB-Verbindungen gehen nicht.
^q-b2tg

Welche Wege zu echtem Parallelismus gibt es in Python?::Prozesse, C- und Rust-Bibliotheken ohne GIL (im Data Engineering der wichtigste), free-threaded Build, Subinterpreter, Numba/Cython mit `nogil` und verteilte Systeme
^q-6nzz

Warum bekommt ein Worker nicht die DB-Verbindung des Hauptprozesses?::Eine Verbindung ist ein Socket mit Sitzungszustand und nicht picklebar. Jeder Worker öffnet eine eigene, z. B. im `initializer` des Pools mit dem DSN.
^q-j9is

## Block 4: Generators, Chunking und Memory Management

Wann chunkt man mit Generator, wann ohne?::Mit Generator, wenn die Daten nicht sicher in den Speicher passen, z. B. `read_csv(chunksize=…)`. Ohne, wenn Chunks nur Arbeitseinheiten sind, z. B. Batches für einen Process Pool.
^q-4ayb

Wann gibt CPython den Speicher eines Objekts frei?::Sobald sein Referenzzähler auf 0 fällt, nicht erst am Funktionsende. Zyklen räumt zusätzlich der zyklische Garbage Collector ab.
^q-bp3j

Was unterscheidet Iterable und Iterator?::Ein Iterable liefert per `iter()` einen Iterator. Der Iterator hält den Zustand, liefert per `__next__` Elemente und wirft am Ende `StopIteration`, die `for` abfängt.
^q-rw33

Warum kann man über eine Liste zweimal iterieren, über einen Generator nur einmal?::`iter(liste)` erzeugt jedes Mal einen neuen Iterator. Ein Generator ist selbst der Iterator, erschöpft bleibt erschöpft, die zweite Schleife läuft still null Mal.
^q-twjc

Wann läuft der Code einer Generator-Funktion, und was passiert bei `yield`?::Der Aufruf liefert nur ein Generator-Objekt, erst `next()` startet den Code. Bei `yield` friert der Frame ein und macht beim nächsten `next()` dahinter weiter.
^q-hwea

Was unterscheidet `sum([x*x for x in …])` von `sum(x*x for x in …)`?::Die List Comprehension materialisiert alle Werte, der Generator-Ausdruck braucht konstanten Speicher. Der Vorteil ist Speicher, nicht Zeit.
^q-8q4a

Wann ist ein Generator die falsche Wahl?::Bei mehreren Durchläufen, wahlfreiem Zugriff, `len()`, Sortieren, kleinen Datenmengen, Übergabe an andere Prozesse oder mehreren lesenden Threads
^q-jav7

Wie funktioniert eine Generator-Pipeline, und wovon hängt ihr Speicherbedarf ab?::Die Kette wird erst beim Konsumieren gezogen (pull), jedes Element läuft einzeln durch. Der Speicher hängt von der Größe eines Elements ab, nicht von der Datenmenge.
^q-c3hf

Welche vier Hebel nennt pandas für große Datenmengen?::Weniger laden (nur benötigte Spalten), effiziente Datentypen wie `category`, Chunking und andere Bibliotheken wie Polars oder DuckDB. Prüfen mit `memory_usage(deep=True)`.
^q-c4xj

Welche Berechnungen gehen chunkweise, welche nicht?::Ja: zeilenweise Operationen und zerlegbare Aggregate wie `sum` oder `mean` über Summe und Anzahl. Nein: Median, `count distinct`, Sortieren und große Joins.
^q-e7pk

Was unterscheidet Client-side und Server-side Cursor?::Client-side lädt beim `execute()` das ganze Ergebnis, `fetchmany` spart dann nichts. Server-side (`conn.cursor(name="x")`) holt Portionen bei konstantem Speicher.
^q-g8q2

Wie streamt man eine Abfrage mit SQLAlchemy?::Mit `execution_options(yield_per=10_000)` und einer Generator-Funktion. Ohne `yield_per` ist schon alles geladen, die Session muss bis zum Ende offen bleiben.
^q-i3ni

Warum wird manuelles Chunking seltener?::Polars (Streaming-Engine) und DuckDB (Out-of-Core) verarbeiten große Daten selbst in Stücken und lagern auf die Platte aus. Man beschreibt nur noch das Was.
^q-iau5

## Block 5: Event Loop, asyncio und asynchrone Programmierung

Was tut der Event Loop?::Er hält eine Sammlung von Jobs und gibt nacheinander jedem die Kontrolle, bis dieser pausiert oder fertig ist. Ohne Arbeit ruht er.
^q-3h3x

Was sind Coroutine-Funktion, Coroutine-Objekt und Task?::Coroutine-Funktion: `async def`. Coroutine-Objekt: ihr Aufruf, führt noch nichts aus. Task: beim Loop angemeldete Coroutine, z. B. per `create_task()`.
^q-4jq4

Blockiert `await` den Event Loop?::Nein. `await coroutine` läuft zunächst wie ein Funktionsaufruf, erst beim Warten auf Unfertiges pausiert der Task und der Loop lässt andere laufen.
^q-atdv

Warum laufen `await coro_a(); await coro_b()` nacheinander, und wie gleichzeitig?::`coro_b` wird erst nach `coro_a` erzeugt. Gleichzeitig laufen sie nur als Tasks, z. B. in einer `asyncio.TaskGroup`. Gleichzeitigkeit entsteht durch Tasks.
^q-yndy

Warum muss man den Rückgabewert von `asyncio.create_task()` festhalten?::Der Loop hält nur eine schwache Referenz, der GC könnte den Task mitten in der Ausführung einsammeln. Oder gleich eine `TaskGroup` nutzen.
^q-buce

Was unterscheidet `asyncio.gather` von `asyncio.TaskGroup` bei Fehlern?::`gather` gibt die erste Exception weiter, die anderen laufen weiter. `TaskGroup` bricht alle ab, liefert eine `ExceptionGroup` und garantiert, dass am Blockende alle Tasks fertig sind (Structured Concurrency).
^q-ciet

Wie setzt man in asyncio Zeitlimits, und was passiert bei `cancel()`?::`async with asyncio.timeout(5):` wirft bei Ablauf `TimeoutError`. `cancel()` wirft `CancelledError` am aktuellen `await`, aufräumen im `finally`, nie verschlucken.
^q-s6kn

Was ist die große Gefahr bei asyncio?::Blockierender Code wie `time.sleep()`, `requests` oder synchrone DB-Treiber hält alle Tasks an, ohne Fehlermeldung. Sichtbar im Debug-Modus mit `debug=True`.
^q-u424

Wie bringt man blockierenden Code in asyncio unter?::I/O mit `asyncio.to_thread()`, CPU-Arbeit in reinem Python mit `run_in_executor` und `ProcessPoolExecutor`. Am besten async Bibliotheken wie `httpx` nutzen.
^q-55t4

Was unterscheidet asyncio von Threads?::asyncio wechselt kooperativ nur an `await`, sehr billig, zehntausende Tasks. Threads wechseln präemptiv überall, teurer, aber mit jeder Bibliothek nutzbar.
^q-58ex

Kann es in asyncio Race Conditions geben?::Ja, über `await`-Grenzen: Zwischen Lesen, `await` und Schreiben können andere Tasks den Zustand ändern. Abhilfe: kein `await` dazwischen oder `asyncio.Lock`.
^q-443z

Wann asyncio, Threads oder Prozesse im Data Engineering?::asyncio: viele API-Aufrufe mit `httpx.AsyncClient`. Threads: I/O mit synchronen Libraries wie `boto3`.  
Prozesse: CPU-Arbeit in Python-Schleifen.
^q-7xaf

Warum nutzt eine FastAPI mit synchroner SQLAlchemy-Session `def`-Routen?::`def` läuft im Threadpool, blockierendes Warten schadet nicht. `async def` blockierte bei jeder Abfrage den Event Loop für alle Requests.
^q-9ntm

Was ist Function Coloring?::`async`-Funktionen lassen sich nur aus `async`-Funktionen aufrufen, `async` frisst sich nach oben durch. Deshalb gibt es viele Bibliotheken doppelt.
^q-hizr

Wie drosselt man zehntausend gleichzeitige Anfragen?::`asyncio.Semaphore(10)` mit `async with sem:` oder eine `asyncio.Queue` mit festen Worker-Tasks und `maxsize` für Gegendruck
^q-q887

## Block 6: SQL vs. Python für ETL

Welche zwei Entscheidungen stecken in „SQL oder Python“?::Die Engine (CPython, Single-Node wie DuckDB, MPP wie Spark) und die Schnittstelle (native Python, DataFrame, SQL). Code ist nur die Schnittstelle zur Engine.
^q-tuwy

Warum muss man native Python von Polars oder DuckDB unterscheiden?::Native Python rechnet langsam in CPython. Polars und DuckDB sind nur Schnittstellen zu deklarativen, spaltenweisen, parallelen Engines.
^q-65g5

Wobei sind SQL-Engines stark, wobei schwach?::Stark bei Joins, Aggregationen und Window Functions. Schwach bei komplexen Schleifen und Rekursion, z. B. für ML-Algorithmen.
^q-fvqg

Wonach wählt man die Schnittstelle zwischen SQL und Python?::Python gewinnt bei Modularität, Tests, nicht tabellarischen Daten, Typprüfung und Bibliotheken. SQL gewinnt bei Lernkurve und der Zahl der Leute, die es lesen können.
^q-gcfy

Was spricht für SQL als Standardwahl, und wann ist es ungeeignet?::Verständlich, zukunftssicher, profitiert ohne Änderung von besseren Engines, mit DuckDB testbar. Ungeeignet bei schwer ausdrückbarer Logik, Graphen und manchen Zeitreihen.
^q-xa5z

Ist SQL schwerer zu testen als Python?::Üblicherweise ja, möglich ist es aber gut: Abfragen in CTEs zerlegen und einzeln mit DuckDB testen. Logik mit vielen Fallunterscheidungen bleibt in Python leichter.
^q-fk9q

Wie lautet die dbt-Faustregel zu SQL vs. Python?::Geht es gleich gut, gut geschriebenes SQL. Geht es in SQL nicht oder nur unlesbar, Python. Kurz: SQL, wo möglich, Python, wo nötig.
^q-tbdk

Was sind Expression und Context in Polars?::Expression: wiederverwendbare Spaltenberechnung wie `pl.col("preis") * 1.1`. Context: wendet sie an, z. B. `select`, `with_columns`, `filter`, `group_by().agg()`.
^q-c7sa

Was macht der Lazy-Modus von Polars?::`scan_*` oder `.lazy()` bauen einen Plan, der erst bei `.collect()` läuft. Der Optimizer schiebt Filter und Spaltenauswahl zum Lesen, Plan per `explain()`.
^q-hnsp

Was bleibt von „SQL oder Python“, wenn DuckDB SQL direkt auf DataFrames ausführt?::Die Engine ist dieselbe, Performance kein Argument mehr. Übrig bleibt die Schnittstellenwahl, und die darf man pro Schritt treffen.
^q-tunj

Wie ordnen sich SQL, Polars, pandas und native Python zwischen deklarativ und imperativ ein?::SQL und Polars lazy deklarativ, Polars eager und pandas mengenorientiert mit selbst festgelegter Reihenfolge, native Python imperativ.
^q-nmdp

Warum ist der Ort der Daten bei Pipelines auf Postgres-Daten wichtig?::Python muss die Daten erst übers Netz holen, nativ sogar als einzelne Objekte. SQL in Postgres rechnet dort, wo sie liegen. Ladezeit beim Vergleich getrennt ausweisen.
^q-k4my

Wie vergleicht man zwei Pipeline-Varianten fair?::Eine Variable pro Messung, mehrere Läufe mit Median, verschiedene Datenmengen, Ladezeit und Spitzenspeicher getrennt. Wartbarkeit an einem konkreten Änderungsszenario messen.
^q-tkeu
