# 2.4 Apache Spark

*Richtwert: 1,5 Wochen*

## Motivation

Wie du in der vergangenen Challenge gesehen hast, ist das manuelle Chunking, Memory Management und Parallisieren extrem mühselig, aufwändig und fehleranfällig. Es zwingt uns die Komplexität unserer Anwendung drastisch zu erhöhen.

Das ist übrigens kein Python-Spezifisches Problem, sondern ein generelles “Big Data” Problem: Sobald unsere Datenmengen zu groß für den Arbeitsspeicher werden und Performance Bottlenecks uns zum parallelisieren zwingen wird es kompliziert.

Wenn es dafür doch nur eine smarte Lösung gäbe…

## Leitfaden / Stichworte

1. Spark vs PySpark
2. JVM und jdbc - und was haben diese Java Technologien mit Spark zu tun?
3. Horizontale vs Vertikale Skalierung
4. Grundprinzipien von Distributed Compute
5. Spark Internals: Cluster-Architektur, Driver, Executor, Cluster Manager, Catalyst, AQE, Partitionierung, Shuffling, Tasks vs Stages vs Jobs
6. DataFrames vs DataSets vs RDDs
7. das .parquet file format
8. lazy evaluation in spark
9. Spark Configuration best practices
10. UDFs

## Kontrollfragen

1. Scala und Java sind JVM Sprachen. Was bedeutet das?
2. DataFrames vs DataSets vs RDDs: Warum sind für uns nur DataFrames interessant?
3. Erkläre das Konzept von actions vs transformations in Spark
4. Was ist Shuffling? Wie ist es zu bewerten, wenn Spark für uns shuffelt?
5. Warum ist “Shuffling” ein irreführender Begriff?
6. Warum ist Spark die unangefochtene nr 1 im Bereich “Distributed Compute Engines”? Was war die revolutionäre Idee dabei? Was war davor?
7. Was ist das parquet file format? Wieso dominiert es die Data Engineering Welt? Was könnten Gründe sein warum es außerhalb dieser Welt eher selten genutzt wird?
8. Beziehe Stellung zur Aussage: “.parquet ist letztlich eine schlauere, kompromierte Form der .csv Datei. Beide speichern strukturierte (tabellenförmige) Daten - parquet macht das nur eben effizienter.”
9. Wie funktioniert Run Length Encoding? Warum ist es in insbesondere im Context “Columnar Storage” so verbreitet?
10. Was gibt es außer SparkCore und SparkSQL noch? Wann könnten diese Bibliotheken hilfreich sein?
11. Spark nimmt uns also vieles ab. Gibt es trotzdem Dinge in Bezug auf Performance und Memory management, die wir als Entwickler noch beachten müssen?
12. Wie sollte ein Spark Cluster ca. Konfiguriert sein? Wie groß sollten Executor sein, wie groß die einzelnen partitionen, wie viele Kerne sollte man pro Executor allokieren,…?
13. Was sind die Hauptgründe für langsame Spark jobs? Was sind die Lösungen dafür und wie debugged man langsame Spark jobs?
14. Python UDF vs Pandas UDF vs Scala UDF vs Spark native solutions. Wann solltest du was nutzen? Woher kommen die Performance Unterschiede?

## Aufgaben

1. Löse die Python Challenge nochmal mit PySpark. Vergleiche die Ergebnisse in Hinblick auf Performance, Skalierbarkeit und Codequality (Leserlichkeit, Wartbarkeit, Erweiterbarkeit). Die nötigen Daten, um das ganze lokal auszuführen kann dir dein Coach zukommen lassen.
2. Mache dich außerdem mit der Spark UI Vertraut. Sie ist beim Debuggen oft enorm hilfreich und - wenn man weiß wie - kannst du darin fast alle relevanten Informationen finden.
